# 데이터 처리 설계 — 운영 적용 전 검토 필요

모바일 서버는 각 교직원의 Google 계정 식별자·이름·이메일, 암호화한 Google 토큰, 개인 설정, 기기별 푸시 구독, 세션 및 저장/발송 상태를 처리하도록 작성되었습니다. 기존 확장프로그램의 개인정보처리방침은 이 구조를 설명하지 않으므로 그대로 적용할 수 없습니다. 운영 전 실제 구현과 보관·탈퇴·토큰 철회 절차를 반영한 방침을 별도로 마련해야 합니다.

- Google 시트 ID는 서버 설정으로 고정. 방문자가 다른 시트를 임의 지정하는 기능 없음.
- 실제 일정은 사용자의 권한으로 조회. 익명·다른 계정과 공유하는 일정 서버 캐시 없음.
- 토큰은 서버 DB에 AES-GCM으로 암호화. 브라우저에 access/refresh token 전달하지 않음.
- 세션 cookie는 HttpOnly, 운영 HTTPS에서 Secure. 쓰기에는 동일 출처·세션·CSRF 확인 적용.
- 푸시 수신 주소는 알려진 브라우저 푸시 서비스의 HTTPS 주소만 허용.
- 서비스 워커는 앱 셸만 캐시하고 `/api/`, `/auth/`는 캐시하지 않음.
- 사용자가 미리보기에서 편집한 예시 데이터는 실제 시트와 분리된 sessionStorage에만 저장.
- 현재 브라우저의 실제 일정 캐시는 메모리이며 새 실행 뒤 오프라인 일정 조회를 보장하지 않음.
- 로그아웃은 해당 세션과 해당 기기 푸시 연결을 제거. 계정 전체 삭제/토큰 철회 기능 및 보관 기한은 운영 전 추가 검토 필요.
- 진단·검증 자료에는 학교 실제 일정 및 토큰을 넣지 않음.
